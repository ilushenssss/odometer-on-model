# Допущения, ограничения и конфигурируемые параметры

## 1. Допущения

**Объект и среда**

1. Трамвай движется только по рельсам, поэтому его положение однозначно задаётся пройденным путём
   $s$ вдоль линии. Боковой ошибки нет (кроме ошибки самой карты).
2. Есть **карта линии**: план (x, y), профиль высот (уклоны), положения платформ. Её можно построить
   один раз по эталонному рейсу с GNSS (`track_from_gnss`, см. [JURY_GUIDE.md](JURY_GUIDE.md)). В
   работе навигатор GNSS не использует.
3. Известно **начальное положение** на линии: $s_0$, точка (x, y) или (широта, долгота),
   проецируемая на линию (`initial_position` / `initial_xy` / `initial_latlon`). Для кольцевых и
   многопутных участков направление движения по карте однозначно (движение «вперёд» по $s$).
4. Движение только вперёд. Скатывание назад под тормозом не моделируется: на стоянке тормоз
   удерживает вагон.
5. Паспортные данные трамвая (тяговая и тормозная характеристики, число осей, какие оси моторные)
   известны приближённо. **Реальная масса, сцепление, износ колёс, КПД тяги, сопротивление движению
   не известны** и оцениваются онлайн.
6. Масса меняется скачками на остановках (пассажиры), износ колёс — медленно, сцепление — быстро
   (погода, листья, неоднородность рельса).

**Входные данные**

7. Ручка контроллера: одно число, линейно отображаемое на $u \in [-1, 1]$ (тяга > 0, торможение < 0,
   экстренное ≤ −0,95). Сила тяги/торможения — известная функция $u$ и $v$ (раздел 3 в
   [MODEL.md](MODEL.md)).
8. Одометрия: ≥ 1 датчик скорости вращения колеса, желательно ≥ 3. Желателен хотя бы один датчик на
   **немоторной** оси: при тяге она не буксует и служит эталоном.
9. Датчики независимы. Их отказы (обрыв, залипание, ноль, выбросы, дрейф масштаба, шум) не
   происходят одновременно у всех каналов, **кроме** полной потери одометрии, которая
   обрабатывается отдельно (счисление по модели).
10. Метки времени входных сообщений монотонны. Если `header.stamp` отсутствует, берётся время приёма.

**Модель**

11. Продольная динамика — одномерная; силы на осях делятся поровну; перераспределение нагрузки
    между осями при ускорении не учитывается.
12. Кривая сцепления имеет форму «крип → пик → падающая ветвь», пик около 2 % проскальзывания.
13. Возмущения (ошибки сопротивления, ветер, неоднородность) — процесс Гаусса–Маркова $d$ с временем
    корреляции 60 с.
14. Длительные остановки (≥ 4 с при работающей одометрии, ≥ 10 с «вслепую») происходят у платформ.
    На этом основана опциональная привязка `nav.station_snap`.

## 2. Ограничения

Кратко (подробно с цифрами и планом — в [LIMITATIONS.md](LIMITATIONS.md)):

* решение проверено на высокоточном симуляторе и на rosbag, записанном с него, но не на реальном
  трамвае;
* **полная потеря одометрии в момент трогания на очень скользких рельсах** — худший случай
  (сценарий `leaves_blackout`: до 15 % пути): модель не знает текущего сцепления;
* общий износ колёс наблюдаем только через привязки к платформам. Без них остаётся ≈ 1,2 % пути;
* одна η объясняет и «тяжелее», и «слабее тяга»: после отказа тягового преобразователя эффективная
  масса смещается (прогноз при этом остаётся верным);
* ядро на Python: среднее время шага ≈ 0,15–0,26 мс, но единичные паузы сборщика мусора
  достигают ~30–45 мс;
* привязка к платформам может ошибиться, если трамвай долго стоит у светофора рядом с платформой.
