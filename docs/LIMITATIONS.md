# Ограничения решения и план развития после хакатона

## 1. Ограничения (с цифрами)

| # | Ограничение | Проявление | Чем смягчено сейчас |
|---|---|---|---|
| 1 | **Проверено только на симуляторе** и rosbag, записанном с него | параметры кривой крипа, тяговой характеристики и шумов — модельные | симулятор намеренно богаче модели навигатора (динамика каждой оси, противобуксовочная система, неизвестные масса/износ/КПД/сопротивление); параметры задаются конфигом, код менять не нужно |
| 2 | **Полная потеря одометрии в момент трогания на очень скользких рельсах** | сценарий `leaves_blackout`: максимальная ошибка 428 м (15 % пути), СКО скорости 3,4 м/с; обычная одометрия там же — 510 м | модель не знает текущего сцепления: если колёса не проскальзывали недавно, μ̂ ближе к «сухому» значению. Сообщаемая σ растёт, режим `BLIND` виден в `/diagnostics` |
| 3 | Длительная полная потеря одометрии в целом | 100–300 с без одометрии: 20–110 м (1–2 % пути) | счисление по адаптированной модели, ZUPT по модели, привязка остановок «вслепую» |
| 4 | **Общий износ колёс** не наблюдаем по одометрии | без привязок к платформам ≈ 1,2 % пути (72 м на 5,9 км) | масштаб $k$ по парам привязок к платформам (с ними 0,1–0,5 %) |
| 5 | Привязка к платформам предполагает, что длинные стоянки — у платформ | стоянка у светофора в пределах 20–60 м от платформы даст неверную привязку | робастная дисперсия, адаптивный гейт, увеличение σ после проскальзывания; привязку можно отключить (`nav.station_snap: false`) |
| 6 | «Тяжелее» и «слабее тяга» неразличимы | после отказа тягового преобразователя оценка массы смещается (70 т при 58 т) | прогноз остаётся верным (ошибка 7 м на 5,9 км) |
| 7 | Отказ **немоторного** (эталонного) датчика при тяге | дрейф его масштаба кратковременно выглядит как буксование моторных осей (до ~4 с, ошибка скорости до 1,5 м/с) | правило «буксование всех моторных осей > 4 с ⇒ отказ эталона», консенсус |
| 8 | Карта из GNSS-трека | боковая ошибка ≈ 1 м (дрейф GNSS), уклоны ≈ ±7 ‰; платформы ищутся по стоянкам ≥ 10 с — долгая нештатная остановка (в демо — после экстренного торможения) принимается за платформу, что дало ложную привязку (ошибка до 48 м вместо 21 м) | сглаживание; строить карту по штатному рейсу в хорошую погоду, проверять столбец `station`; можно подать точную карту (CSV) |
| 9 | Лёд | СКО скорости на уровне обычной одометрии, выигрыш только в положении (47 м против 90 м) | — |
| 10 | Python | среднее время шага 0,15–0,32 мс, но единичные паузы сборщика мусора до ~30–45 мс; CPU 13–15 % ядра при 50 Гц (в основном накладные расходы rclpy) | бюджет и превышения публикуются в `/diagnostics`; алгоритм переносится в C++ без изменений (5 состояний, O(1)) |
| 11 | Одномерная модель | нет перераспределения нагрузки по осям, бокового движения, упругости сцепки | не требуется для рельсового транспорта при заданной точности |
| 12 | Одна линия, движение вперёд | стрелки, разворотные кольца, движение назад не поддерживаются | задать отдельную карту для маршрута; `set_position` для переинициализации |
| 13 | RBF-аппроксиматор остатка | в экспериментах не дал устойчивого выигрыша, при отказах датчиков вредит | выключен по умолчанию, оставлен как опция |

## 2. План развития после хакатона

**Этап 1 — реальные данные (1–2 месяца)**

1. Записать rosbag с реального трамвая: ручка, все датчики колёс, **ток и напряжение тяговых
   двигателей** (если доступны), GNSS/RTK как эталон, двери.
2. Идентифицировать параметры по записям: тяговая и тормозная характеристики, $c_0, c_1, c_2$,
   инерционность привода, кривая крипа; уточнить шумы.
3. Построить карты маршрутов по RTK-рейсам и проверить точность на полном круге маршрута в разную
   погоду (сухо / дождь / листопад / гололёд).

**Этап 2 — точность в трудных случаях (2–3 месяца)**

4. **Сцепление без проскальзывания:** оценивать запас сцепления по току двигателя и отклику колеса
   (момент → ускорение колеса), вести карту сцепления по участкам пути и погоде. Это закрывает
   ограничение 2.
5. Сигнал открытия дверей → надёжная привязка к платформам (ограничение 5); стрелки и перегоны как
   дополнительные ориентиры.
6. Совместная оценка массы (по току и ускорению) и КПД тяги раздельно (ограничение 6).
7. Сглаживатель (RTS) для постобработки и сглаженный вывод положения без скачков коррекции.
8. Мультигипотезный фильтр для многопутных участков и стрелочных переводов.

**Этап 3 — промышленная реализация (3–4 месяца)**

9. Перенос ядра на **C++** (фиксированные матрицы 5×5, без динамической памяти, детерминированное
   время < 50 мкс), нода `rclcpp`, lifecycle node, `ros2_control`-совместимые интерфейсы.
10. Функциональная безопасность: независимый контроль правдоподобия (сторожевой канал), журналирование
    отказов, интеграция с системой управления движением; оформление по ГОСТ Р / EN 50128 / EN 50129.
11. Комплексирование с другими источниками при их наличии (GNSS, ИНС, балиса, лидар по
    инфраструктуре) — модель остаётся «ядром» и резервом при их отказе.
12. CI: воспроизведение набора rosbag с метриками при каждом изменении, регрессионные пороги.

**Этап 4 — эксплуатация**

13. Онлайн-обучение параметров по флоту (износ, масса, сопротивление по вагонам) и серверная карта
    сцепления, обновляемая всеми трамваями маршрута.
14. Мониторинг: дашборд точности, задержки, отказов датчиков; предиктивное обслуживание датчиков
    колёс по статистике отказов.
